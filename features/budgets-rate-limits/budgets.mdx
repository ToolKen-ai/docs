Toolken checks your monthly spend cap at the gateway before forwarding the request. When the cap is hit, the gateway returns a `402` and the provider is never called.

<Warning>Self-serve budget configuration is coming soon. Budget caps today are set by the Toolken team. [Contact us](mailto:hello@toolken.ai) to configure a cap for your account.</Warning>

## What you see when the budget is exceeded

The gateway returns an OpenAI-compatible error body you can parse with any existing error handler.

```json
{
  "error": {
    "message": "Monthly budget exceeded",
    "type": "proxy_error",
    "param": null,
    "code": "budget_exceeded"
  }
}
```

## How enforcement works

The gateway checks each request against your monthly cap before forwarding it. If the request would push you over the cap, it is rejected with a `402` and your provider is never called. Spend is tracked in real time, so the cap holds even under bursty traffic.

<Note>If the enforcement backend is briefly unavailable, requests are allowed through rather than blocked. Toolken prioritizes availability over hard-blocking during transient disruptions. This means budgets are a strong control but not an absolute guarantee during such windows -- a brief disruption may allow a small number of requests to pass even after the cap has been reached.</Note>

## Watching your spend today

You do not need to wait for a budget alert to track costs. The dashboard shows cumulative spend by model, provider, feature, customer, and any custom dimension you send. Use it to catch runaway usage before a cap is hit.

See [Observability](/features/observability/overview) for a walkthrough of the cost views.
